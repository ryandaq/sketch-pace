# Stroke measurement research

Researched 2026-10-15 for Sketch Pace. This folder contains a [repository catalog](repositories.md), the current [scoring design](measurement-design.md), [functional checks](test-scoring.js), a [current benchmark](benchmark.js), and [benchmark notes](benchmarks.md). The [drawing app landscape](drawing-app-landscape.md) surveys current products and links each practice pattern to the new Exploration Lab; [Lab implementation notes](exploration-lab.md) explain the 34 modes and scoring limits. Lab checks live in [test-lab.js](test-lab.js) and [test-lab-ui.js](test-lab-ui.js). The earlier product-form build is retained as [historical benchmark code](benchmark-v4.js) with local snapshots. No third-party code was copied into the app or this folder.

## Ranked methods for this app

The order weighs measurement validity for a known target, runtime, implementation complexity, and whether a method preserves visible mistakes. Runtime labels below are algorithmic estimates except where the local benchmark is cited. The repositories are examples and evidence of the underlying methods; the implementation in `app.js` is original.

| Rank | Method | Value here | Work | Decision |
|---:|---|---|---|---|
| 1 | Equal-distance resampling of raw strokes | Makes mean deviation and ellipse residual much less sensitive to how many events a mouse or pen emits in each part of a stroke. Supported by [$1 Recognizer](https://github.com/nok/onedollar-unistroke-coffee) and [Squiggy](https://github.com/LingDong-/squiggy#preprocessing). | O(n + k) for n raw and k output points | **Implemented:** 64 line samples; 96 ellipse samples. |
| 2 | Squared point-to-segment distance, square root once after finding the minimum | Speeds nearest-curve checks without changing Euclidean distance. [Simplify.js source](https://github.com/mourner/simplify-js/blob/master/simplify.js) uses squared segment distance. | O(n) per query | **Implemented** for axis dots and box edge placement. |
| 3 | Fixed-budget bidirectional contour distance | Both stroke-to-reference and reference-to-stroke terms penalize wandering and missing a section. The nearest-segment primitive appears in [Turf](https://github.com/Turfjs/turf/blob/master/packages/turf-nearest-point-on-line/index.ts) and [cheap-ruler](https://github.com/mapbox/cheap-ruler). | O(k²) with k=96, bounded | **Historical:** used for the removed cup study; retained as research for future form work. |
| 4 | Direct residual to the known circle or ellipse | The target center, axes, and angle are already known. A direct normalized radial residual checks placement and shape in one pass, with axis dots, coverage, closure, and path excess as separate checks. [OpenCV's ellipse fitting](https://github.com/opencv/opencv/blob/5.x/doc/tutorials/imgproc/shapedescriptors/bounding_rotated_ellipses/bounding_rotated_ellipses.markdown) is useful background, but fitting a new ellipse would remove target placement from the score. | O(k) | **Retained and improved** with equal-distance samples. |
| 5 | High-frequency pen event capture | [perfect-freehand's maintainers](https://github.com/steveruizok/perfect-freehand/issues/58) recommend coalesced pointer events when fast touch strokes lose samples. Better capture may improve fidelity, but needs device testing and can increase raw point counts. | O(n) input work | **Candidate** for iPad testing. |
| 6 | Least-squares circle fit | [circle-fit](https://github.com/Meakk/circle-fit) provides center, radius, and residual in linear time. Useful for a future diagnostic such as “your circle is too large” even when the target dots are missed. | O(n) | **Not added** to the score because the current target-relative metric already checks intended center and radius. |
| 7 | Direct least-squares ellipse fit | [OpenCV](https://github.com/opencv/opencv) and [EllipseFit](https://github.com/seisgo/EllipseFit) can infer freeform axes and angle. This would help a later free-sketch analysis mode, but a fitted ellipse can give a misplaced yet internally regular ellipse a good score. | O(n) data pass plus small solver | **Deferred**. |
| 8 | Full gesture-template recognition | [$1 Recognizer](https://github.com/nok/onedollar-unistroke-coffee) resamples and normalizes position, scale, and rotation. Its recognition goal differs from measuring accuracy relative to fixed dots. | O(k × templates × rotations) | **Adopted only its resampling principle**. |
| 9 | Polyline simplification | [Simplify.js](https://github.com/mourner/simplify-js) and [Paper.js](https://paperjs.org/tutorials/paths/smoothing-simplifying-flattening/) reduce points for rendering and editing. Simplification can erase the wobble this practice app needs to measure. | Often near O(n), data dependent | **Do not simplify the scored path**. |
| 10 | Smoothing or Bézier fitting before scoring | [perfect-freehand](https://github.com/steveruizok/perfect-freehand), [Paper.js](https://paperjs.org/tutorials/paths/smoothing-simplifying-flattening/), and [fit-curve](https://github.com/odiak/fit-curve) can make drawn marks look clean. Scoring those adjusted curves would hide hand-control errors. | More work than the direct residual | **Keep rendering and scoring on the raw geometry**. |

The original rankings were for fixed-target practice, including an earlier cup drill, rather than universal claims about which repositories are fastest. See [benchmarks.md](benchmarks.md) for historical before/after timings and their limits. The current box uses a nine-edge assignment method described in [measurement-design.md](measurement-design.md).
